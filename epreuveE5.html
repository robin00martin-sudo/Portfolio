Calendrier de jours fériés

Aperçu du projet

Présentation

  • Projet réalisé au GRETA dans le cadre du BTS SIO — contexte professionnel réel.
  • Application web permettant de générer automatiquement un calendrier annuel intégrant les jours fériés français, calculés dynamiquement selon l'année choisie.
  • Chaque utilisateur peut personnaliser l'affichage et exporter le résultat en PDF directement depuis le navigateur, sans dépendance à une bibliothèque externe.
  • Les données des formations sont stockées en base SQL et administrables via un panneau de gestion dédié, permettant d'ajouter ou modifier les formations sans toucher au code.

Fonctionnalités

  • Génération automatique du calendrier annuel avec jours fériés
  • Personnalisation de l'affichage par l'utilisateur
  • Export PDF depuis le navigateur
  • Panneau d'administration des formations
  • Stockage et lecture des données via base SQL

Architecture

  • Front-end — affichage dynamique du calendrier en JavaScript, mise en page CSS responsive
  • Back-end PHP — calcul des jours fériés, requêtes SQL, génération des données pour la vue
  • Base de données SQL — stockage des formations et de leur planification
  • Export PDF — déclenché côté navigateur via JavaScript

Technologies

PHP JavaScript CSS HTML SQL

Gestion des rôles utilisateurs

Aperçu du projet

Présentation

  • Application web développée en PHP selon le patron MVC (Modèle – Vue – Contrôleur), structurée en trois couches bien séparées : Modele/, vue/ et controleur/.
  • Permet la gestion complète des utilisateurs : inscription avec hashage du mot de passe (password_hash), authentification sécurisée, et déconnexion avec destruction de session.
  • Un administrateur peut créer des rôles (ex. : admin, user) et les affecter dynamiquement à chaque utilisateur via un formulaire dédié.
  • Toutes les interactions avec la base de données passent par des requêtes préparées PDO, protégeant l'application contre les injections SQL.
  • Le routage est centralisé dans le controleurPrincipal qui distribue les actions (connexion, inscription, liste, affectation) vers le bon contrôleur.

Fonctionnalités

  • Inscription et connexion sécurisées avec hashage des mots de passe
  • Gestion de session PHP (connexion / déconnexion)
  • Création et liste des rôles
  • Affectation d'un rôle à un utilisateur
  • Liste de tous les utilisateurs enregistrés

Architecture MVC

  • Modele/bd.inc.php — connexion PDO à la base de données
  • controleur/ — un fichier par action (connexion, inscription, rôle, affectation…)
  • vue/ — templates d'affichage HTML séparés du code métier
  • index.php — point d'entrée unique, dispatch via ?action=

CasZerne – Gestion d'une caserne de pompiers volontaires

Aperçu du projet

Présentation

  • Application web développée en PHP orienté objet selon le patron MVC, structurée en trois couches bien séparées : Core/ (modèle métier), vue/ et controleur/.
  • Permet la gestion complète d'une caserne de pompiers volontaires : ajout/suppression de volontaires identifiés par leur numéro de BIP, planification de périodes de garde par tranche horaire (Matin, Après-midi, Nuit), et suivi du compteur de gardes effectuées.
  • Chaque volontaire peut se voir affecter une activité par période : Disponible, Missionné ou Absent, avec la possibilité de marquer s'il est effectivement de garde via la table AVOIR_ACTIVITE.
  • Toutes les interactions avec la base de données sont gérées par des classes DAO dédiées (PompierDAO, PeriodeDAO, ActiviteDAO) utilisant des requêtes préparées PDO, protégeant l'application contre les injections SQL.
  • Le routage est centralisé dans controleurPrincipal qui distribue les actions (liste, ajout, suppression, détail) vers le bon contrôleur via le paramètre ?action= de l'URL.

Fonctionnalités

  • Liste, ajout et suppression de pompiers volontaires
  • Fiche détail d'un pompier avec ses activités
  • Planification de périodes de garde (date + tranche horaire)
  • Affectation d'une disponibilité à chaque volontaire par période
  • Compteur de gardes effectuées mis à jour automatiquement
  • Suppression en cascade des activités liées à une période

Architecture MVC

  • Core/ — classes métier (Pompier, Periode, Caserne, CollectionPompier) et DAOs dans Core/DAO/
  • modele/Connexion.php — singleton PDO d'accès à la base de données
  • controleur/ — un fichier par action (listePompiers, ajouterPeriode, detailPeriode, ajouterActivite…)
  • vue/ — templates HTML d'affichage séparés du code métier
  • index.php — point d'entrée unique, dispatch via ?action=
